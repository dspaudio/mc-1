# Validation record — experimental 0.1

## Verified locally on the development Mac

- C11 host compilation with `-Wall -Wextra -Werror -Wconversion`.
- 12 non-silent, distinct preset renders; 16 non-silent drum models; envelope release and hat choke.
- LA allocator bounded at eight shared voices; acid mono/slide behavior checked on all three parts.
- Bit-identical audio across 64-frame and 4096-frame render subdivision.
- Bar-boundary pattern switching and a 60-second exact swing/tempo counter check.
- Part mute, transport stop, project range validation, serialization round trip and corruption rejection.
- A/B flash model: 6,228 interrupted erase/program positions retain the previous valid project;
  corrupted newest record falls back; sequence rollover is handled.
- UI drum sound/step/hit/level actions, save confirmation and all strip output bounds.
- AddressSanitizer and UndefinedBehaviorSanitizer test run, with abort on first error: pass.
- In-app browser: actual C drum screen displayed; audio enable, transport and pause controls worked;
  no console warnings/errors were reported during that interaction.

`sizeof(McEngine) = 2920`, `sizeof(McProject) = 2112` on the host. The 10-second host stress
render initially took approximately 0.02 s optimized / 0.05 s sanitized on this Mac. This is
only host CPU time, not pi32v2 timing. Reproducible audio metrics are generated by
`python3 tools/verify_audio.py` and retained in `docs/audio-report.json`.

## Target compilation

The official JieLi compiler archive was downloaded and hashed. Local Docker starts stalled
in Created state, including bare `uname` probes on both architectures; unrelated containers
were left untouched. The native Linux target CI job is the build authority. Its successful
artifact, when available, includes ELF, raw app, symbols, disassembly and exact memory report.
This record will be updated after the first CI result; target compilation is not yet claimed here.

## Not verified

No hardware has been flashed or accessed by this task. Boot, codec audio, keyboard mapping,
encoder directions, real flash saves, power-failure behavior, UBOOT recovery, battery/master ADC,
CPU clock, stack high-water, worst-case ISR deadline and long-duration stability are untested.
No installable update package or hardware-tested release is provided. Host audio and screenshots
must not be described as recordings or photographs of a real FM-1.
